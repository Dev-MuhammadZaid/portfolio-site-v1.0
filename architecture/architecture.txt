5. DESIGN TOKEN SYSTEM

---

All major visual values should be controlled through CSS custom properties.

Color Tokens:

--primary-color
--accent-color
--bg-color
--surface-color
--text-color
--text-muted
--border-color

Radius Tokens:

--radius-sm
--radius-md
--radius-lg
--radius-xl

Shadow Tokens:

--shadow-sm
--shadow-md

Transition:

--transition

The purpose of this system is to prevent individual components from creating unrelated colors, border radiuses, and shadows.

Components should consume the global tokens instead of defining their own theme values whenever possible.

6. THEME ARCHITECTURE

---

The project supports two visual themes:

Light Theme
Default :root variables.

Dark Theme
body.dark-theme variables.

JavaScript is responsible only for changing the theme state.

CSS is responsible for defining how each theme looks.

The selected theme is stored in localStorage so the user's preference can persist between page visits.

7. JAVASCRIPT RESPONSIBILITIES

---

JavaScript contains only behavior that requires interaction or browser APIs.

Theme
- Read saved theme.
- Apply dark theme.
- Toggle light/dark mode.
- Save the selected theme.
- Update theme icon.

Navigation
- Open mobile navigation.
- Close mobile navigation.
- Update aria-expanded.
- Update navigation button label.
- Update menu icon.
- Close navigation after selecting a link.

Scroll
- Detect page scroll position.
- Show/hide scroll-to-top button.
- Scroll to the top smoothly.

15. MAINTAINABILITY RULES

---

1. Do not create a new color when an existing design token can be reused.

2. Do not duplicate common button styles.

3. Use .btn for shared button behavior.

4. Use .section-card for shared section styling.

5. Keep JavaScript focused on behavior.

6. Keep visual styling inside CSS.

7. Keep content inside HTML.

8. Use semantic HTML before adding ARIA.

9. Use ARIA only when it provides additional accessibility information.

10. Keep naming consistent.

11. Remove unused variables and selectors.

12. Avoid unnecessary abstractions for a small vanilla JavaScript project.

13. Preserve the current v1 feature scope unless a new feature is intentionally planned.

14. Keep light and dark themes controlled through CSS variables.

15. Test the page after every structural or CSS refactor.

16. SENIOR DEVELOPMENT FORMULA

---

Before changing a component, identify:

Goal
What should this component achieve?

Structure
Which HTML elements represent it?

Style
Which design tokens control it?

Behavior
Does JavaScript need to control it?

Accessibility
Can keyboard and assistive-technology users operate it?

Responsive Behavior
How should it behave on smaller screens?

Reusability
Can the common behavior be extracted into a reusable class?

18. ARCHITECTURAL PRINCIPLE

---

Keep the project simple, readable, reusable, accessible, and maintainable.

Do not introduce frameworks, build tools, unnecessary folders, or complex abstractions unless the project's requirements justify them.

The architecture should support future growth without making the current v1 unnecessarily complicated.
